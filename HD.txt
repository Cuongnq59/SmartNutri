Phân hệ 2: Quản lý Chi tiêu & Scan Hóa đơn (Smart Budget & Receipt OCR)
	2.1. Quét hóa đơn siêu thị / Chợ tiện lợi:



	Mô tả: Chụp hóa đơn thanh toán từ các siêu thị (WinMart, Bách Hóa Xanh, Co.opmart...) hoặc ảnh chụp bill chuyển khoản QR khi mua đồ ăn. 

	Xử lý: OCR trích xuất tên mặt hàng, số lượng, đơn giá, tổng tiền, ngày mua. 

	Cập nhật dữ liệu:


	Tự động cộng số tiền vào danh mục "Chi phí ăn uống" trong tuần. 

	Đưa các nguyên liệu thô (thịt heo, ức gà, trứng gà, đậu phụ...) vào kho ảo "Tủ lạnh của bạn". 

	2.2. Theo dõi Hạn mức Chi tiêu (Budget Watchdog):



	Thiết lập ngân sách ăn uống tối đa theo tuần hoặc tháng (ví dụ: 1.500.000 VNĐ / tháng hoặc 350.000 VNĐ / tuần). 

	Thanh tiến độ trực quan: Hiển thị lượng tiền đã tiêu, lượng tiền còn lại mỗi ngày và cảnh báo khi mức chi tiêu vượt tốc độ dự kiến (Burn Rate Warning). 

Phân hệ 3: Tính năng "Chế độ Tiết kiệm Mục tiêu" & Tận dụng Tủ lạnh
	3.1. Smart Leftovers (Nấu gì với tủ lạnh hiện tại):



	Input: Danh sách thực phẩm đang có trong tủ lạnh (lưu tự động từ hóa đơn hoặc tick chọn thủ công: ví dụ còn 3 quả trứng, 2 bìa đậu phụ, nửa cây bắp cải). 

	Xử lý: AI sinh công thức món ăn nhanh, dễ nấu bằng các thiết bị sinh viên phổ biến (chảo chống dính, nồi cơm điện). 

	Output: 2–3 gợi ý món ăn, thời gian nấu, hàm lượng protein đạt được và mức calo tương ứng. 

	3.2. Target Budget Meal Planner (Bữa ăn tiết kiệm mục tiêu - Core Differentiator):



	Mục tiêu: Giải quyết bài toán: "Tôi còn 40.000 VNĐ cho ngày hôm nay và cần nạp thêm ít nhất 50g protein để tăng cân/tăng cơ. Tôi nên mua gì?"


	Logic tính toán:


	Sử dụng bảng tham chiếu giá thực phẩm bình dân địa phương (cập nhật định kỳ: Trứng gà công nghiệp ~2.800đ/quả = 6.5g protein; Đậu phụ ~4.000đ/bìa = 10g protein; Ức gà ~65.000đ/kg = 31g protein/100g; Cá nục, gan heo...). 

	Tối ưu hóa hàm chi phí: 

min⁡("Cost" ) "sao cho" ∑▒"Protein" ≥"Target", ∑▒"Calories" ≈"Goal" 
	Xuất danh sách mua sắm: "Mua 2 lạng ức gà (13k) + 2 bìa đậu (8k) + 2 quả trứng (6k) = 27k VNĐ → Cung cấp 68g protein". 

Phân hệ 4: Hồ sơ Thể trạng & Báo cáo Tiến độ
	4.1. Khởi tạo mục tiêu thể trạng cá nhân hóa:



	Nhập chiều cao, cân nặng, giới tính, mức độ vận động (tính toán RMR/TDEE). 

	Lựa chọn lộ trình: Tăng cân nạc (Lean Bulk), Giảm mỡ (Cut), Duy trì thể trạng (Maintain). 

	Tính toán chỉ số mục tiêu mỗi ngày: Tổng Calo, Protein (g), Carbs (g), Fat (g). 

	4.2. Dashboard phân tích tuần/tháng:



	Biểu đồ cột: So sánh lượng calo nạp thực tế vs calo mục tiêu qua từng ngày. 

	Tỷ lệ hoàn thành mục tiêu Protein theo ngày. 

	Chỉ số Chi phí trên từng gram Protein (Cost per Gram of Protein - CPGP): Chỉ số độc quyền giúp người dùng biết tuần này mình nạp dinh dưỡng có "kinh tế" hay không (ví dụ: trung bình tốn 450đ cho 1g protein).

3. Cấu trúc bảng CSDL chi tiết cho Hóa đơn & Tủ lạnh
SQL
-- 1. Bảng lưu lịch sử quét hóa đơn và biến động ngân sách
CREATE TABLE receipt_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    merchant_name VARCHAR(150),
    total_amount DECIMAL(12, 2) NOT NULL,
    food_amount DECIMAL(12, 2) NOT NULL,
    receipt_image_url VARCHAR(500),
    purchase_date DATE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 2. Bảng Tủ lạnh ảo (Virtual Pantry)
CREATE TABLE pantry_items (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    ingredient_ref_id BIGINT,             -- Khóa ngoại đến bảng nguyên liệu chuẩn
    custom_name VARCHAR(150) NOT NULL,    -- Tên hiển thị (ví dụ: Ức gà WinMart)
    quantity DECIMAL(8, 2) NOT NULL,      -- Số lượng hiện có
    unit VARCHAR(20) NOT NULL,            -- g, piece, pack...
    cost_paid DECIMAL(12, 2),             -- Giá tiền đã mua
    purchase_date DATE NOT NULL,
    expiry_date DATE,                     -- Ngày hết hạn dự kiến
    status VARCHAR(20) DEFAULT 'ACTIVE',  -- ACTIVE (Còn), CONSUMED (Đã ăn), EXPIRED (Bỏ)
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (ingredient_ref_id) REFERENCES local_ingredients_ref(id)
);
(Nguồn DDL schema)

    public NutritionAnalysisResponse analyzeMealImage(byte[] imageBytes, String mimeType) {
        String base64Image = Base64.getEncoder().encodeToString(imageBytes);

        // Payload gửi Gemini API
        Map<String, Object> requestBody = Map.of(
            "contents", List.of(
                Map.of(
                    "parts", List.of(
                        Map.of("text", USER_PROMPT_INSTRUCTION),
                        Map.of("inline_data", Map.of(
                            "mime_type", mimeType,
                            "data", base64Image
                        ))
                    )
                )
            ),
            "generationConfig", Map.of(
                "response_mime_type", "application/json",
                "temperature", 0.2 // Giữ nhiệt độ thấp để số liệu nhất quán
            )
        );

        return restClient.post()
                .uri("/models/gemini-1.5-flash:generateContent?key={key}", apiKey)
                .contentType(MediaType.APPLICATION_JSON)
                .body(requestBody)
                .retrieve()
                .body(NutritionAnalysisResponse.class);
    }

PHẦN 4: THUẬT TOÁN TỐI ƯU HÓA BỮA ĂN TIẾT KIỆM (MILP MODEL)
Bài toán gợi ý thực đơn tiết kiệm chi phí nhưng vẫn đảm bảo dinh dưỡng là một biến thể của Bài toán Dinh dưỡng Stigler (The Stigler Diet Problem) kết hợp giữa Quy hoạch tuyến tính nguyên hỗn hợp (MILP) và Knapsack Problem đa ràng buộc. 


1. Mô hình hóa Toán học
Biến số (Decision Variables)
Cho tập hợp N loại thực phẩm sinh viên: i∈{1,2,…,N}. 


	x_i≥0: Số đơn vị khẩu phần (serving unit) của thực phẩm i. 


	Thực phẩm đóng gói/quả (trứng, xúc xích, đậu bìa, hộp sữa): x_i∈Z_(≥0) (Số nguyên). 

	Thực phẩm cân theo lạng (ức gà, thịt nạc, gạo, rau): x_i∈R_(≥0) (Số thực). 

Tham số đầu vào (Parameters)
	c_i: Đơn giá trên mỗi đơn vị (VNĐ). 

	p_i: Lượng protein trên mỗi đơn vị (g). 

	k_i: Lượng calories trên mỗi đơn vị (kcal). 

	u_i: Giới hạn khẩu phần tối đa trong bữa/ngày (tránh ngộ độc hoặc ngán). 

	Mục tiêu người dùng: P_min (Protein tối thiểu), [K_min,K_max ] (Khoảng calo an toàn), B_max (Ngân sách tối đa). 

Hàm mục tiêu & Hệ ràng buộc
	Hàm mục tiêu: Tối thiểu hóa chi phí: 

min⁡Z=∑_(i=1)^N▒c_i ⋅x_i
	Ràng buộc:


	Ràng buộc Protein: ∑_(i=1)^N▒p_i ⋅x_i≥P_min


	Ràng buộc Calories: K_min≤∑_(i=1)^N▒k_i ⋅x_i≤K_max


	Ràng buộc Ngân sách: ∑_(i=1)^N▒c_i ⋅x_i≤B_max


	Ràng buộc Khẩu vị: 0≤x_i≤u_i  (∀i)

public class MealOptimizerService {

    public MealPlanResult optimizeMeal(double targetProtein, double minCalories, double maxCalories, double maxBudget) {
        // Tải solver SCIP (Solving Constraint Integer Programs)
        MPSolver solver = MPSolver.createSolver("SCIP");
        if (solver == null) {
            throw new IllegalStateException("Không tìm thấy SCIP Solver");
        }

        List<FoodItem> items = getStudentFoodCatalog();
        MPVariable[] x = new MPVariable[items.size()];

        // 1. Khai báo biến quyết định
        for (int i = 0; i < items.size(); i++) {
            FoodItem item = items.get(i);
            if (item.isDiscrete()) {
                // Biến nguyên (trứng, bìa đậu, hộp sữa)
                x[i] = solver.makeIntVar(0, item.getMaxPortion(), "item_" + item.getId());
            } else {
                // Biến thực (lạng thịt, lạng gạo)
                x[i] = solver.makeNumVar(0.0, item.getMaxPortion(), "item_" + item.getId());
            }
        }

        // 2. Ràng buộc Protein: sum(p_i * x_i) >= targetProtein
        MPConstraint proteinConstraint = solver.makeConstraint(targetProtein, Double.POSITIVE_INFINITY, "Protein");
        for (int i = 0; i < items.size(); i++) {
            proteinConstraint.setCoefficient(x[i], items.get(i).getProtein());
        }

        // 3. Ràng buộc Calo: minCalories <= sum(k_i * x_i) <= maxCalories
        MPConstraint caloConstraint = solver.makeConstraint(minCalories, maxCalories, "Calories");
        for (int i = 0; i < items.size(); i++) {
            caloConstraint.setCoefficient(x[i], items.get(i).getCalories());
        }

        // 4. Ràng buộc Ngân sách: sum(c_i * x_i) <= maxBudget
        MPConstraint budgetConstraint = solver.makeConstraint(0, maxBudget, "Budget");
        for (int i = 0; i < items.size(); i++) {
            budgetConstraint.setCoefficient(x[i], items.get(i).getCost());
        }

        // 5. Hàm mục tiêu: min sum(c_i * x_i)
        MPObjective objective = solver.objective();
        for (int i = 0; i < items.size(); i++) {
            objective.setCoefficient(x[i], items.get(i).getCost());
        }
        objective.setMinimization();

        // 6. Thực thi giải thuật
        MPSolver.ResultStatus resultStatus = solver.solve();
        if (resultStatus == MPSolver.ResultStatus.OPTIMAL || resultStatus == MPSolver.ResultStatus.FEASIBLE) {
            return buildMealPlan(items, x, objective.value());
        } else {
            // Không tìm được thực đơn thỏa mãn ngân sách -> Gợi ý tăng ngân sách tối thiểu
            return handleInfeasibleCase(targetProtein, minCalories);
        }
    }
}
(Nguồn mã nguồn giải thuật) 


3. Xử lý trường hợp biên (Edge Cases)
	Trường hợp không khả thi (Infeasible): Nếu ngân sách quá thấp so với chỉ tiêu protein, solver thông báo số tiền tối thiểu tuyệt đối cần bù thêm thay vì báo lỗi. 

	Đa dạng hóa món ăn (Variety Constraint): Khống chế mỗi món không chiếm quá 60% tổng lượng protein của bữa để tránh tình trạng chỉ gợi ý một món duy nhất (như ức gà). 

	Ưu tiên nguyên liệu sẵn có (Pantry Deduction): Trừ lượng dinh dưỡng của đồ trong tủ lạnh trước khi giải hệ phương trình (các món này tính phí 0 VNĐ).
